## 1. Goal

Create the pnpm monorepo skeleton exactly as the architecture's repository layout shows, with empty apps and packages that each build, plus a local infrastructure compose file (Postgres 16, Redis 8.8, Adminer), an `.env.example`, and the root scripts the rest of the track uses. No application code.

## 3. Scope

In scope: repo root config, `apps/web`, `apps/api`, `apps/worker`, `apps/lockdown` (empty placeholder), `packages/proctor-sdk`, `packages/shared`, `infra/docker-compose.yml`, `infra/caddy/`, `infra/judge0/`, `infra/scripts/`, `prisma/` (folder only), `.github/workflows/`, `.env.example`, `.gitignore` additions.

## 5. Step-by-step deliverables

1. **Workspace root**: `package.json` (private, `packageManager` pinned, `engines.node` `>=24 <25`, `@types/node` `^24`, scripts below), `pnpm-workspace.yaml` (`apps/*`, `packages/*`), `.nvmrc` (`24`), `.editorconfig`, `.prettierrc`, root `tsconfig.base.json` with `"strict": true`, ESLint config enforcing `@typescript-eslint/no-explicit-any` as an error. Append `.gitignore` entries: node_modules, `.env`, dist, `.next`, coverage, `__pycache__`, `.venv`, `*.log`, local DB volumes. Keep `.DS_Store`.
2. **TypeScript packages** `apps/web`, `apps/api`, `packages/proctor-sdk`, `packages/shared`, `apps/lockdown`: each has `package.json`, `tsconfig.json` extending the base, `src/index.ts` (or equivalent empty module) and a `build` script that succeeds (a plain `tsc` build is enough; Next.js and NestJS are installed in FE-01 and BE-01).
3. **`apps/worker`**: `pyproject.toml` (Python 3.12), `src/worker/__init__.py`, and a `package.json` wrapper with a `build` script (for example compile-all) so `pnpm -r build` covers it. No FastAPI yet.
4. **`infra/docker-compose.yml`**:
   - `postgres:16`: named volume, `pg_isready` healthcheck, port 5432, credentials from env.
   - `redis:8.8` (pin the tag; used under its AGPLv3 licence option, ADR 0001): healthcheck `redis-cli ping`, append-only on, `--maxmemory-policy noeviction` (BullMQ needs it; verify against current BullMQ docs).
   - `adminer`: port 8080, depends on postgres being healthy.
   - Placeholder dirs `infra/caddy/`, `infra/judge0/`, `infra/scripts/` with `.gitkeep`.
5. **`.env.example`**: `DATABASE_URL` (local example URL), `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `REDIS_URL`, plus empty or `change-me` placeholders, each with a one-line comment naming the step that will use it: web origin and API port (BE-01; placeholder origins `https://assess.yourcompany.com` and `https://staging.assess.yourcompany.com`, D-30, to be confirmed), access and candidate JWT secrets (BE-02, BE-07), one AES-256-GCM encryption key (TOTP secrets and session HMAC keys, BE-02, BE-07), S3-compatible storage settings `S3_ENDPOINT`, `S3_REGION`, `S3_FORCE_PATH_STYLE`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_MEDIA_BUCKET`, `S3_BACKUP_BUCKET` (BE-09, DB-07; Cloudflare R2 on staging, AWS S3 on pilot and production, where the EC2 instance role may replace the access keys; ADR 0001 section 2.1; no provider-specific variable names), email provider key and from address (BE-06; one key covers every template, including the consent copy, password reset and erasure notice), Judge0 URL and auth token (BE-05), Sentry DSNs (DEP-01), `MIGRATION_DATABASE_URL` and `APP_USER_PASSWORD` (DB-03; the owner-role URL for migrations, and the local-only password that `infra/scripts/set-app-user-password.mjs` gives `app_user` after the DB-03 migration creates it, ADR 0006 section 7; staging, pilot and production set it at provisioning), `OTP_PEPPER` (BE-07; key for hashing candidate OTPs, ADR 0003), `REQUIRE_LEGAL_APPROVED_CONSENT=false` (BE-07; true on pilot and production, ADR 0007). Mark the list "derived from the prompts and ADRs 0001 to 0009; ARC-03 may revise". Never put a real secret in it.
6. **Root scripts**: `dev:infra` (compose up with `--wait` so it returns when healthy), `dev:infra:down`, `dev:infra:reset`, plus `db:migrate`, `db:seed` and `db:reset`.
   - The `db:*` scripts are wired to the Prisma CLI, a root dev dependency, through root `prisma.config.ts`, with `prisma/schema.prisma` as the schema path. Prisma 7 reads the URL and the seed command from that file (ADR 0009 section 4.1).
   - **Localhost guard (review S4, ADR 0009 section 4.4).** The checks are in `infra/scripts/local-db-guard.mjs`, and `infra/scripts/assert-local-db.mjs` runs them.
     - `db:migrate` and `db:seed` run `node infra/scripts/assert-local-db.mjs` first.
     - `db:reset` is `sh infra/scripts/db-reset`, with the final text given in ADR 0009 section 4.4. It adds the agent-marker check and the Compose-port check (D-37).
     - `dev:infra:reset` is `sh infra/scripts/dev-infra-reset`. It refuses a Docker engine that is not local (SF5).
     - `prisma.config.ts` throws if `.env` defines Prisma's consent variable.
     - Agents never run `db:reset` or `dev:infra:reset`; a human does. This is policy, backed by speed bumps (D-38).
   - The `db:*` scripts may fail with "no schema" until DB-02 and DB-03; say so in the PR.
   - Also add root `lint`, `typecheck`, `test` and `build` scripts (`pnpm -r`), because every agent's definition of done requires them.
7. **CI (PA-01, approved by D-25)**: `.github/workflows/ci.yml` on pull requests and pushes to main.
   - It runs install (frozen lockfile), lint, typecheck, test and build.
   - Node comes from `.nvmrc` (24), and pnpm from `packageManager` through `corepack enable`. Corepack is bundled with Node 24 (ADR 0009).
   - It adds the consent-variable check from ADR 0009 section 4.4.
   - Use only official actions pinned to a major version or commit, and no repository secrets.
8. Run the verification below, fix problems, commit in small steps.

## 7. Acceptance criteria (definition of done)

- `pnpm install` succeeds from a clean clone.
- `pnpm -r build` succeeds for every app and package.
- `pnpm lint` and `pnpm typecheck` pass and reject `any`.
- `pnpm dev:infra` brings up postgres, redis and adminer; `docker compose -f infra/docker-compose.yml ps` shows postgres and redis healthy.
- `psql $DATABASE_URL -c 'select 1'` returns 1.
- `.env.example` has no real secrets; `.env` is git-ignored.
- **Guard and consent checks (ADR 0009 section 4.4; SF2).** They are verified only by `pnpm test`, through `infra/scripts/*.test.mjs`.
  - The tests run each script with an explicit environment, with stand-in `docker` and `pnpm` on `PATH`. Nothing reaches a reset.
  - **The agent never runs `pnpm db:reset` or `pnpm dev:infra:reset`, not even to watch a refusal.**
  - The tests cover:
    - non-local, empty and non-postgres URLs;
    - `host`, `hostaddr` and `service` query parameters;
    - the libpq redirect variables;
    - the consent variable;
    - every agent marker;
    - the Compose-port mismatch;
    - a missing terminal;
    - `CI`;
    - a non-local Docker engine.
  - CI runs Node 24, the consent-variable check, `prisma version` and shellcheck.
- Repository layout matches architecture.md (apps/web, api, worker, lockdown; packages/proctor-sdk, shared; infra/docker-compose.yml, caddy, judge0; prisma/; .github/workflows/).
- PR lists files changed, commands run with results, tool versions, and notes: Q-39 (NestJS is not set up here; DB-05 will add a minimal module if BE-01 has not run) and PA-01 status.
- Reported back for code-reviewer review; you do not merge.
