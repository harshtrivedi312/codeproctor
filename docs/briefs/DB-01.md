## 5. Step-by-step deliverables

1. **Workspace root**: `package.json` (private, `packageManager` pinned, scripts below), `pnpm-workspace.yaml` (`apps/*`, `packages/*`), `.nvmrc`, `.editorconfig`, `.prettierrc`, root `tsconfig.base.json` with `"strict": true`, ESLint config enforcing `@typescript-eslint/no-explicit-any` as an error. Append `.gitignore` entries: node_modules, `.env`, dist, `.next`, coverage, `__pycache__`, `.venv`, `*.log`, local DB volumes. Keep `.DS_Store`.
2. **TypeScript packages** `apps/web`, `apps/api`, `packages/proctor-sdk`, `packages/shared`, `apps/lockdown`: each has `package.json`, `tsconfig.json` extending the base, `src/index.ts` (or equivalent empty module) and a `build` script that succeeds (a plain `tsc` build is enough; Next.js and NestJS are installed in FE-01 and BE-01).
3. **`apps/worker`**: `pyproject.toml` (Python 3.12), `src/worker/__init__.py`, and a `package.json` wrapper with a `build` script (for example compile-all) so `pnpm -r build` covers it. No FastAPI yet.
4. **`infra/docker-compose.yml`**:
   - `postgres:16`: named volume, `pg_isready` healthcheck, port 5432, credentials from env.
   - `redis:8.8` (pin the tag; used under its AGPLv3 licence option, ADR 0001): healthcheck `redis-cli ping`, append-only on, `--maxmemory-policy noeviction` (BullMQ needs it; verify against current BullMQ docs).
   - `adminer`: port 8080, depends on postgres being healthy.
   - Placeholder dirs `infra/caddy/`, `infra/judge0/`, `infra/scripts/` with `.gitkeep`.
5. **`.env.example`**: `DATABASE_URL` (local example URL), `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `REDIS_URL`, plus empty or `change-me` placeholders, each with a one-line comment naming the step that will use it: web origin and API port (BE-01), access and candidate JWT secrets (BE-02, BE-07), one AES-256-GCM encryption key (TOTP secrets and session HMAC keys, BE-02, BE-07), R2 account id, endpoint, access key, secret key, media bucket, backup bucket (BE-09, DB-07), email provider key and from address (BE-06), Judge0 URL and auth token (BE-05), Sentry DSNs (DEP-01). Mark the list "derived from the prompts; ARC-03 may revise". Never put a real secret in it.
6. **Root scripts**: `dev:infra` (compose up with `--wait` so it returns when healthy), `db:migrate`, `db:seed`, `db:reset`, wired to the Prisma CLI installed as a root dev dependency with `prisma/schema.prisma` as the schema path. They may fail with "no schema" until DB-02 and DB-03; say so in the PR. Also add root `lint`, `typecheck`, `test`, `build` scripts (`pnpm -r`), because every agent's definition of done requires them.
7. **CI (PA-01, only if approved by then)**: `.github/workflows/ci.yml` running install, lint, typecheck, test. If PA-01 is not approved when you open the PR, leave the workflow out and say so in the PR.
8. Run the verification below, fix problems, commit in small steps.

## 7. Acceptance criteria (definition of done)

- `pnpm install` succeeds from a clean clone.
- `pnpm -r build` succeeds for every app and package.
- `pnpm lint` and `pnpm typecheck` pass and reject `any`.
- `pnpm dev:infra` brings up postgres, redis and adminer; `docker compose -f infra/docker-compose.yml ps` shows postgres and redis healthy.
- `psql $DATABASE_URL -c 'select 1'` returns 1.
- `.env.example` has no real secrets; `.env` is git-ignored.
- Repository layout matches architecture.md (apps/web, api, worker, lockdown; packages/proctor-sdk, shared; infra/docker-compose.yml, caddy, judge0; prisma/; .github/workflows/).
- PR lists files changed, commands run with results, tool versions, and notes: Q-39 (NestJS is not set up here; DB-05 will add a minimal module if BE-01 has not run) and PA-01 status.
- Reported back for code-reviewer review; you do not merge.
