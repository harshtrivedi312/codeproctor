## 1. Goal

Create `prisma/schema.prisma` so that it matches the reference DDL in /docs/database.md exactly: all 31 tables, all 20 enums, unique constraints, foreign keys with the same ON DELETE behavior, indexes, column types and defaults. database.md already contains every approved delta. ADR 0008 lists each delta against the original DDL (commit 7f5c6b9) as a checklist. List everything Prisma cannot express so DB-03 can add it in SQL.

## 5. Step-by-step deliverables

1. **Datasource and generator (Prisma 7, ADR 0009 sections 4.1 and 4.2).**
   - **Datasource:** `datasource db { provider = "postgresql" }` with **no `url`**. Prisma 7 rejects `url` in the schema file. The CLI reads `MIGRATION_DATABASE_URL` from `prisma.config.ts`. The app connects with `DATABASE_URL` through the adapter.
   - **Generator:** `provider = "prisma-client"`, `output = "../apps/api/src/generated/prisma"`, `moduleFormat = "cjs"`.
   - **Client factory:** `createPrismaClient(connectionString)` returns `new PrismaClient({ adapter: new PrismaPg({ connectionString }) })`. It is the only place that constructs a client.
   - Do not enable preview features unless the architect approves; extensions are handled in DB-03.
2. **Enums (20)**, each with `@@map` to the snake_case DB type and a PascalCase Prisma name. Keep value names and order exactly as in the DDL.
   - **Base 13:** user_role, difficulty, question_type, proctor_profile (STANDARD, STRICT only), session_status (adds DECLINED), submission_kind, media_stream, severity, risk_band, verdict, flag_decision, appeal_status, event_type (39 values).
   - **New 7:** pause_reason, client_kind, event_source, identity_check_status, identity_review_reason, identity_manual_decision, question_scoring.
   - **Name clash:** the `flag_decision` enum must not collide with the `FlagDecision` model. Choose a distinct Prisma enum name (for example `FlagDecisionValue`) and keep `@@map("flag_decision")`.
3. **Models (31)** with `@@map` to table names and `@map` on snake_case columns; camelCase fields.
   - Identity: Organization, User, RefreshToken, AuditLog.
   - Content: Question, QuestionVersion, TestCase, QuestionVariant, VariantTestCase, AiReferenceSolution.
   - Delivery: Test, TestSection, TestQuestion, Candidate, Invitation, Session, SessionSection, SessionQuestion, Submission.
   - Proctoring: ConsentText, Consent, IdentityCheck, MediaChunk, ProctorEventBatch, ProctorEvent, KeystrokeBatch.
   - Review: SessionReview, FlagDecision, Appeal.
   - Integrations: WebhookEndpoint, WebhookDelivery.
4. **Types.**
   - `@db.Uuid` with `@default(dbgenerated("gen_random_uuid()"))` for uuid primary keys.
   - `@db.Citext` for `users.email` and `candidates.email`.
   - `@db.Inet` for `audit_logs.ip` and `consents.ip`.
   - `@db.Timestamptz(6)` for every timestamptz, with `@default(now())` where the DDL has it.
   - `Decimal` with the DDL precision: `numeric(6,2)` for weights, points and scores; `numeric(8,2)` for `sessions.total_score`; `numeric(5,4)` for `face_match_score`, `identity_checks.threshold` and `confidence`.
   - `BigInt` for bigint columns: `audit_logs.id`, `media_chunks.id`, `proctor_events.id`, `keystroke_batches.id`, `webhook_deliveries.id`, `media_chunks.size_bytes`, `sessions.paused_ms`, `session_sections.time_limit_ms`, `flag_decisions.event_id`.
   - `Int @db.SmallInt` for `identity_checks.attempt` and `proctor_event_batches.event_count`.
   - `Bytes` for `proctor_event_batches.signature` and `keystroke_batches.signature`.
   - `String[]` for `text[]` with an empty-array default where the DDL has one.
   - `PauseReason[]` with an empty default for `sessions.pause_reasons`.
   - `Json` for jsonb with the DDL defaults (`{}`, `[]`, and the `limits` default `{"cpu_ms":2000,"wall_ms":5000,"memory_kb":262144}`).
5. **Unique constraints (20) and composite primary keys (3).**
   - **Unique:**
     - users.email; users.set_password_token_hash
     - refresh_tokens.token_hash
     - questions (org_id, slug); question_versions (question_id, version)
     - tests (id, org_id); candidates (org_id, email); candidates (id, org_id)
     - invitations.token_hash; invitations (id, org_id)
     - sessions.invitation_id; session_sections (session_id, position)
     - consent_texts (org_id, version); consents.session_id
     - identity_checks (session_id, attempt); media_chunks (session_id, stream, seq); keystroke_batches (session_id, seq)
     - session_reviews.session_id; flag_decisions.event_id; appeals.session_review_id
   - **Composite PKs:** session_sections (session_id, section_id), variant_test_cases (variant_id, test_case_id), proctor_event_batches (session_id, seq).
6. **Foreign keys and referential actions.**
   - **ON DELETE CASCADE on exactly these 22:**
     - refresh_tokens.user_id
     - question_versions.question_id; test_cases.question_version_id; question_variants.question_version_id
     - variant_test_cases.variant_id; variant_test_cases.test_case_id
     - ai_reference_solutions.question_version_id; ai_reference_solutions.variant_id
     - test_sections.test_id; test_questions.section_id
     - session_sections.session_id; session_questions.session_id; submissions.session_question_id
     - consents.session_id; identity_checks.session_id; media_chunks.session_id
     - proctor_event_batches.session_id; proctor_events.session_id; keystroke_batches.session_id
     - session_reviews.session_id; flag_decisions.event_id
     - webhook_deliveries.endpoint_id
   - **ON DELETE SET NULL on exactly 1:** webhook_deliveries.session_id.
   - **Composite FKs (3):** invitations (test_id, org_id) → tests (id, org_id); invitations (candidate_id, org_id) → candidates (id, org_id); sessions (invitation_id, org_id) → invitations (id, org_id). They replace single-column FKs on those columns.
   - **Every other FK** has no ON DELETE clause in the DDL, which means NO ACTION. Prisma's defaults differ (Restrict for required relations, SetNull for optional ones, and onUpdate Cascade), so set `onDelete: NoAction` and `onUpdate: NoAction` explicitly where the DDL has no clause, and verify in the generated SQL.
7. **Circular relations.** `questions.current_version_id` → `question_versions` and `organizations.current_consent_text_id` → `consent_texts`. Make each optional, with named relations (for example `"QuestionCurrentVersion"` and `"QuestionVersions"`) so Prisma can tell the two relations between the same models apart. NO ACTION on delete.
8. **Indexes Prisma can express (22 non-partial).**
   - audit_logs (org_id, created_at DESC); users (org_id)
   - refresh_tokens (user_id); refresh_tokens (family_id)
   - test_cases (question_version_id); question_variants (question_version_id); variant_test_cases (test_case_id); ai_reference_solutions (question_version_id)
   - tests (org_id); test_sections (test_id); test_questions (section_id)
   - invitations (test_id); invitations (candidate_id)
   - sessions (status); sessions (org_id, status); session_questions (session_id); submissions (session_question_id, created_at)
   - proctor_events (session_id, occurred_at); proctor_events (session_id, severity)
   - session_reviews (reviewer_id); appeals (assigned_to)
   - webhook_deliveries (endpoint_id, created_at DESC)
9. **TODO list for DB-03**, as a comment block at the top of `schema.prisma` and in the PR description. At minimum:
   - extensions `pgcrypto` and `citext` (first lines of the init migration);
   - the 12 CHECK constraints in ADR 0008 section 5;
   - partial indexes on sessions(risk_band) where status in ('GRADED','UNDER_REVIEW') and on sessions(retention_anchor_at) where it is not null;
   - the trigger for users.updated_at;
   - `GENERATED ALWAYS AS IDENTITY` on the five bigint identity columns (Prisma's autoincrement normally emits a serial-style default, so check the generated SQL and decide with the architect whether to convert in the migration);
   - the circular FK `fk_current_consent_text`, if Prisma does not emit it;
   - any other difference you find in the generated SQL.
10. **Check against the DDL.**
    - Run `pnpm prisma validate`, `pnpm prisma format` and `pnpm db:generate`, then `pnpm typecheck` with the generated client present.
    - Generate SQL into the scratch directory and do not commit it: `pnpm prisma migrate diff --from-empty --to-schema prisma/schema.prisma --script -o <scratch>/init.sql`. Prisma 7 removed `--to-schema-datamodel`; `-o` writes to a file.
    - Compare table, column, enum, index and FK counts and ON DELETE text with database.md and ADR 0008 section 1. Record the result in the PR.

## 7. Acceptance criteria (definition of done)

- `pnpm prisma validate`, `pnpm prisma format` and `pnpm db:generate` pass. `pnpm lint`, `pnpm typecheck` and `pnpm build` still pass with the generated client present, and CI runs `pnpm db:generate`.
- `schema.prisma` has no `url`, and its generator is `prisma-client`. `apps/api/src/generated/` is git-ignored and is not linted.
- `@prisma/client`, `@prisma/adapter-pg` and the `prisma` CLI are the same exact version.
- Exactly 31 models and 20 enums.
- Every DDL column, default, unique, FK and index is present, or listed in the TODO for DB-03 with the reason.
- The 22 ON DELETE CASCADE relations and the 1 SET NULL match. All others are NO ACTION for delete and update (verified in the generated SQL).
- No invented columns. Every line of ADR 0008 sections 2 to 7 is ticked in the PR, and each delta is cited by its ADR number.
- The PR description includes: commands run and results, the DB-03 TODO list, any difference found between Prisma output and the DDL, and anything the architect or PM must decide.
- Reported back for architect review, then code-reviewer; you do not merge.
