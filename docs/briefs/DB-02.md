## 1. Goal

Create `prisma/schema.prisma` so that it matches the reference DDL in /docs/database.md exactly: all 24 tables, all 13 enums, unique constraints, foreign keys with the same ON DELETE behavior, indexes, column types and defaults. Apply only the deltas that ARC-01's freeze list approved. List everything Prisma cannot express so DB-03 can add it in SQL.

## 2. Read first

1. /CLAUDE.md
2. /docs/database.md, all of it. The reference DDL is authoritative over the ERD.
3. /docs/prompts/database.md: Step 2 (this task) and Step 3 (what you hand over)
4. /docs/adr/0008-schema-freeze-list.md and the ADRs it cites (0002 to 0007), plus /docs/adr/0001-overall-architecture.md (Accepted)
5. /docs/status.md section 6 group A for background only. Do not act on a question that the freeze list did not approve.

## 3. Scope

In scope: `prisma/schema.prisma`; Prisma as a dev dependency if DB-01 did not add it; `pnpm prisma validate` and `pnpm prisma format`.

Out of scope: migrations (DB-03), seed (DB-04), PrismaService and client extensions (DB-05), any column, table or enum not in database.md or the freeze list. If the DDL and the freeze list disagree, or you think a column is wrong, stop and ask the PM; do not invent or drop columns.

## 4. Inputs and dependencies

- Monorepo and compose from DB-01 (Postgres reachable is useful but not required for validate and diff).
- The freeze list. If it says "no schema change", use database.md as written.

## 5. Step-by-step deliverables

1. Datasource `postgresql` using `DATABASE_URL`; generator `prisma-client-js`. Do not enable preview features unless the architect approves (extensions are handled in DB-03).
2. **Enums (13)**, each with `@@map` to the snake_case DB type: user_role, difficulty, question_type, proctor_profile, session_status, submission_kind, media_stream, severity, risk_band, verdict, flag_decision, appeal_status, event_type. Use PascalCase Prisma names. The `flag_decision` enum must not collide with the `FlagDecision` model; choose a distinct Prisma enum name (for example `FlagDecisionValue`) and keep `@@map("flag_decision")`. Keep value names exactly as in the DDL.
3. **Models (24)** with `@@map` to table names and `@map` on snake_case columns; camelCase fields. Identity: Organization, User, RefreshToken, AuditLog. Content: Question, QuestionVersion, TestCase, QuestionVariant. Delivery: Test, TestSection, TestQuestion, Candidate, Invitation, Session, SessionQuestion, Submission. Proctoring: Consent, IdentityCheck, MediaChunk, ProctorEvent, KeystrokeBatch. Review: SessionReview, FlagDecision, Appeal.
4. **Types**: `@db.Uuid` with `@default(dbgenerated("gen_random_uuid()"))` for uuid primary keys; `@db.Citext` for `users.email` and `candidates.email`; `@db.Inet` for `audit_logs.ip` and `consents.ip`; `@db.Timestamptz(6)` for every timestamptz with `@default(now())` where the DDL has it; `Decimal` with the DDL precision (`numeric(6,2)` for weights, points, scores; `numeric(8,2)` for `sessions.total_score`; `numeric(5,4)` for `face_match_score` and `confidence`); `BigInt` for bigint columns (`audit_logs.id`, `media_chunks.id`, `proctor_events.id`, `keystroke_batches.id`, `media_chunks.size_bytes`, `sessions.paused_ms`, `flag_decisions.event_id`); `String[]` for `text[]` with an empty-array default; `Json` for jsonb with the DDL defaults (`{}`, `[]`, and the `limits` default `{"cpu_ms":2000,"wall_ms":5000,"memory_kb":262144}`).
5. **Unique constraints**: users.email; refresh_tokens.token_hash; questions (org_id, slug); question_versions (question_id, version); candidates (org_id, email); invitations.token_hash; sessions.invitation_id; consents.session_id; media_chunks (session_id, stream, seq); keystroke_batches (session_id, seq); session_reviews.session_id; flag_decisions.event_id.
6. **Foreign keys and referential actions.** ON DELETE CASCADE on exactly these 15: refresh_tokens.user_id; question_versions.question_id; test_cases.question_version_id; question_variants.question_version_id; test_sections.test_id; test_questions.section_id; session_questions.session_id; submissions.session_question_id; consents.session_id; identity_checks.session_id; media_chunks.session_id; proctor_events.session_id; keystroke_batches.session_id; session_reviews.session_id; flag_decisions.event_id. Every other FK has no ON DELETE clause in the DDL, meaning NO ACTION. Prisma defaults differ (Restrict for required relations, SetNull for optional ones, and onUpdate Cascade), so set `onDelete: NoAction` and `onUpdate: NoAction` explicitly where the DDL has no clause, and verify in the generated SQL.
7. **Circular relation** `questions.current_version_id` to `question_versions`: optional, with named relations (for example `"QuestionCurrentVersion"` and `"QuestionVersions"`) so Prisma can tell the two relations between the same models apart. NO ACTION on delete.
8. **Indexes Prisma can express**: audit_logs (org_id, created_at DESC); sessions (status); submissions (session_question_id, created_at); proctor_events (session_id, occurred_at) and (session_id, severity).
9. **TODO list for DB-03** as a comment block at the top of `schema.prisma` and in the PR description. At minimum: extensions `pgcrypto` and `citext` (first lines of the init migration); five CHECK constraints (organizations.retention_days 7 to 730; tests.duration_minutes 5 to 480; test_questions question_version_id or random_rule not null; invitations window_end greater than window_start; sessions.risk_score 0 to 100); partial index on sessions(risk_band) where status in ('GRADED','UNDER_REVIEW'); trigger for users.updated_at; `GENERATED ALWAYS AS IDENTITY` on the four bigint identity columns (Prisma's autoincrement normally emits a serial-style default, so check the generated SQL and decide with the architect whether to convert in the migration); any other difference you find in the generated SQL.
10. **Check against the DDL**: run `pnpm prisma validate`, `pnpm prisma format`, then generate SQL with `prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script` into the scratch directory (do not commit it) and compare table, column, enum, index and FK counts and ON DELETE text with database.md. Record the result in the PR.

## 7. Acceptance criteria (definition of done)

- `pnpm prisma validate` and `pnpm prisma format` pass.
- Exactly 24 models and 13 enums; every DDL column, default, unique, FK and index present, or listed in the TODO for DB-03 with the reason.
- The 15 ON DELETE CASCADE relations match; all others are NO ACTION for delete and update (verified in generated SQL).
- No invented columns; every approved delta from the freeze list is applied and cited by ADR number.
- PR description includes: commands run and results, the DB-03 TODO list, any difference found between Prisma output and the DDL, anything the architect or PM must decide.
- Reported back for architect review, then code-reviewer; you do not merge.
